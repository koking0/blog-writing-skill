# 博客写作

把一个主题、素材或外文文章整理成读者愿意读、搜索引擎能理解、可以直接发布的博客文章。用户用中文提出请求时默认输出中文；除非用户另有要求，保留必要的英文专有名词并在首次出现时给出简短解释。

本 Skill 提炼自一篇实际的博客写作与 SEO 教程及其中文翻译：保留“真实表达、先完成再修改、先重质量再求数量”的写作心态，以及“选题 → 关键词 → 资料 → 结构 → 文体 → 起草 → 校稿 → SEO 设置 → 发布宣传”的工作流；不要把原文的具体数字、平台设置或个人经历当成所有文章的硬性规则。

## 工作方式

1. **先界定读者和目标。** 明确文章是观点文、体验文、教程文、整理文、比较文，还是几种类型的组合；说明读者读完后应获得的答案或行动。信息不全时做最小假设，并在成稿中标出仍需用户确认的事实。
2. **提出可执行的选题。** 从用户问题、真实经历、读者反馈、时事、竞品/热门文章和关键词需求中找切入点。AI 可用于发散和整理，但不能替代作者的判断、体验和证据。
3. **做轻量关键词研究。** 选一个主关键词和若干相关词，优先使用目标读者真正会搜索的说法。关键词自然出现在标题、开头、小标题、摘要、Slug 和正文中；禁止堆砌、改坏语气或为 SEO 捏造内容。
4. **先备资料再写。** 对教程、比较、整理和事实性文章，记录来源、发布日期、适用版本和待核实点；把外部事实与作者观点区分开，并保留可点击链接。
5. **设计可调整的大纲。** 用清晰的 H1/H2/H3 层级组织内容。标题可采用“如何/清单/问题+答案/数字/指南/综合”结构，但必须准确、具体、避免标题党。长文应有目录、分段、小结或 FAQ；写作过程中允许滚动调整大纲。
6. **先写初稿，再做多轮编辑。** 开头尽快回答“这篇文章解决什么问题、适合谁、为什么值得读”；段落短而完整，使用列表、表格、加粗和示例帮助扫读。润色时检查逻辑、语句、错别字、事实时效、链接、图片、孤行/寡行和重复内容。
7. **让文章具有长期价值。** 对会过期的信息标注日期、版本或更新方式；能沉淀为支柱型内容时，补足定义、案例、边界、常见问题和后续维护建议。不要为了凑字数扩写。

## 翻译与改写

- 如果输入是外文文章，先读原文再写中文，不逐句硬译；保留原文论点、条件、事实和语气，中文表达要自然、易扫读。
- 首段或文末注明原文标题、作者、原文链接、翻译/整理性质和适用的许可或授权信息。没有明确授权时，不声称“已获授权”；只根据页面可见许可或用户提供的授权写合规说明。
- 对原文的个人经历、收入、数据、推荐和平台操作，使用“原文作者提到/文章建议”而不是改写成自己的事实；发现时效风险时标注“截至某日期”或建议复核。
- 转载图片或外部素材时保留来源、替代文本和许可边界；没有必要时优先用自己的示意图或只保留链接。

## SEO 与 Markdown 输出

成稿通常包含：标题、可选的一句话摘要、正文、必要的目录/FAQ、参考链接和图片说明。若目标平台支持，可另外提供：Meta Title、Meta Description、Slug、主关键词和标签；不要把平台专属字段混进正文，除非用户要求。

图片需要同时考虑内容价值和可访问性：提供简短、准确的 `alt` 文本；有解释作用时使用 caption；图片风格和尺寸尽量一致并压缩体积。不要为了“每段一图”机械加图，也不要用图片代替关键文字。

FAQ 只回答文章中真实出现、且对读者有帮助的问题。问题可以来自用户反馈、评论、搜索联想或审阅过程；不要固定添加某个问题，也不要为了 SEO 生搬硬造。

## 发布边界与检查

默认只生成 Markdown 或草稿。只有用户明确要求发布到指定平台时，才执行平台操作；发布前检查标题、标签/分类、摘要、原创/翻译类型、原文链接、图片上传、预览和授权声明。发布后以页面成功提示或文章页面为证据，不把“点击发布”当成成功；若页面显示审核中，准确说明“已提交、等待审核”。
